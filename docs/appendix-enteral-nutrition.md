# 経腸栄養剤の計算仕様

## 概要

本アプリケーションでは、様々な経腸栄養剤の投与量計算に対応している。
理論値（kcal/mL）ではなく、**実製剤のパッケージ規格に合わせた計算**を行うことで、
現場での準備作業を効率化している。

---

## 投与量の計算方法

### 基本方針

実製剤のパッケージ規格を基準とした換算係数を使用する。

**理由**：
- 規格単位の割付（本数計算）と整合しやすい
- 在庫管理が効率的
- 現場の準備が容易

### 複数規格がある場合

同一製剤に複数の規格（パッケージサイズ）がある場合、
**大きい方の規格を計算基準**とする。

**例**：1.5倍濃度の製剤
```
規格A：200 mL（300 kcal）
規格B：267 mL（400 kcal）← こちらを基準に採用

計算基準：267 mL / 400 kcal = 0.6675 mL/kcal
```

### 計算例

**必要エネルギー**：1099 kcal

**投与量計算**：
```
1099 kcal × (267/400) ≒ 733.58 mL → 734 mL（四捨五入）
```

**割付候補**：
```
267 mL × 2本 = 534 mL（800 kcal）
200 mL × 1本 = 200 mL（300 kcal）
───────────────────────────────
合計：734 mL（1100 kcal）
```

**結果**：端数なしで割付完了

---

## 丸め誤差について

実製剤のパッケージ規格（割付）と、mL/kcal の換算・丸め（四捨五入）により、
必要エネルギー（計算値）と実投与カロリー（製剤ベース）に差が生じることがある。

**例**：
- 必要エネルギー：1099 kcal（計算値）
- 実投与カロリー：1100 kcal（製剤ベース）
- 差分：+1 kcal

この差は：
- パッケージ規格と丸め仕様による構造的なもの
- アプリ上は差が分かるように表示する
- 差の解釈は施設の運用・臨床判断に従う

### 丸め仕様
- kcal：四捨五入（0.5は切り上げ）
- g（1桁）：四捨五入（0.05は切り上げ）
- 水分mL：切り上げ
- 経腸mL：四捨五入（0.5は切り上げ）

---

## 実装

### データ構造

各製剤は、**組成（Composition）** と **規格候補（Packages）** をまとめた製剤テーブルで管理している。

組成は、内部では「1 kcal あたり（per kcal）」の係数で保持する。

- `VolumePerKcal`：mL / kcal  
- `ProteinPerKcal`：g / kcal  
- `FatPerKcal`：g / kcal  
- …（以下同様）

ただし、実コードでは添付文書やメーカー公開情報の「○○ kcal あたり」の値をそのまま入力できるように、
`PerPack(packKcal, volumeMl, ...)` ヘルパーで **per kcal に正規化**してテーブル化している。

一方、規格候補（Packages）は、**mL単位のパッケージサイズ一覧**を整数値で保持する。

記述例：
```csharp
// PerPack(packKcal, Volume(mL), 蛋白質(g), 脂質(g), 糖質(g), 食塩(g), VitK(µg), 水分(mL))
// Packages: パッケージサイズ(mL)を整数で記述
[EnteralFormulaType.SampleA] =
    new(
        PerPack(400, 267, 16.0, 12.0, 56.0, 1.22, 28.0, 205),
        new[] { 200, 267 }),
```
内部的には次のように解釈される
```csharp
// packKcal=400 の値を per kcal に正規化
VolumePerKcal  = 267.0 / 400.0; // mL/kcal
ProteinPerKcal = 16.0  / 400.0; // g/kcal
FatPerKcal     = 12.0  / 400.0; // g/kcal
// ...

// Packages は mL 単位の規格候補をそのまま保持
Packages = [200, 267];
```
※イノラスは実規格が 187.5mL だが、Packages は整数管理のため 187 として扱っている（旧WebForms互換）。

### 設計意図

**kcal 基準を採用した理由**：
1. **必要エネルギー（kcal）から投与量（mL）への換算が明確**で、割付候補の提示と整合しやすい
    - 例：必要エネルギーが 1200 kcal なら、1.5倍製剤は 267mL(400kcal)×3本 = 801mL を優先して割付したい
    - 換算：1200 × (267/400) = 801mL（= 400kcalパックを3本に揃えられる）
    - 比較：1200 kcal なら、200mL(300kcal)×4本 = 800mL という割付もできるが、本数が増えてしまう
2. **添付文書との対応**：製剤の成分表は「○○ kcal あたり」で記載されている
3. **データ入力の容易性**：添付文書の数値をそのまま転記しやすい
4. **保守性**：成分変更時の更新が簡単
5. **可読性**：テーブル定義が直感的

※数値は添付文書/メーカー公開情報に基づきますが、実務上の割付（規格・本数）を優先するため、近似や丸めを含みます。

## 新製剤の追加

新しい経腸栄養剤を追加する場合：

1. 製剤の規格を確認（パッケージサイズとカロリー）
2. 複数規格がある場合、アプリ内で割付候補を優先したい規格を決める（推奨：本数を抑えやすい大きい方の規格）
3. 添付文書から成分を転記して反映する
4. パッケージ規格は整数（mL）で入力する

反映先：

- 製剤Enum（UI表示・選択肢）：`Domain/Enums/EnteralFormulaType.cs`
- 製剤テーブル（成分 + 規格の実データ）：`Domain/Tables/EnteralFormulaTable.cs`
