# UI / 設計判断メモ

この文書は **現行UI方針の要約** と、保守時に参照価値のある **重要な判断履歴（archive）** をまとめる。

---

## 1. Current snapshot / 現行方針の要約

### 1-1. 結果表示の優先順位
- 主結果（必要エネルギー・蛋白・水分・推定CCr）を第一面で表示する。
- 参考値（基礎代謝量・BMI・標準体重・肥満度・体表面積）は折りたたみ側に分離する。
- 目的は「BMRを必要エネルギーと誤認しない」情報設計。

### 1-2. 同期方向（エネルギーと経腸栄養）
- 同期は **必要エネルギー → 経腸栄養量** の一方向。
- 経腸栄養量の手動変更で必要エネルギーを上書きしない。
- エネルギー手動編集解除（自動計算に戻す導線）を用意する。

### 1-3. 互換・再発防止ポイント
- IE系では `details` の開閉表示同期に注意（`open` 属性だけに依存しない）。
- モバイルでは「主結果は常時把握、参考値は必要時展開」を維持する。

## 2. Key decision history / 重要なUI変更履歴

### 2026-03-12 結果欄の再設計（BMR誤認対策）
- 主結果と参考項目の視覚的優先度を分離。
- PCは主結果/参考の役割分担を明確化した2領域構成。
- モバイルは1列で「上部＝要点」「折りたたみ内＝参考・補足」に整理。

### 2026-02-15 エネルギー↔経腸の同期方向見直し
- 相互同期を廃止し、一方向同期へ変更。
- 医療現場の流れ（必要量計算→投与量決定）に合わせて、操作の違和感と保守複雑性を低減。

### 2026-02-03〜2026-02-04 例外設定と表示整理
- 疾患セレクトを「例外設定」として明確化。
- 例外時の補足表示を簡潔化し、判断に必要な情報を優先表示。

### 2026-01 UI土台の転換
- 結果/入力の責務分離（AJAX再計算・結果パネル同期）を導入。
- 採用体重の見せ方・用語を整理し、計算ロジックとUI語彙の不一致を縮小。
