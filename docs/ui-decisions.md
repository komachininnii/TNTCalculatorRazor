# UI / 設計判断メモ

## 2026-03-12 結果欄の再設計（BMR誤認対策）

### 背景
- 結果欄で基礎代謝量（BMR）を必要エネルギーと誤認する事例があった。
- 主結果と参考値の視覚的な優先順位が十分に分かれていなかったため、結果欄の情報設計を見直した。

### PC 2列
- 左カラムを「主要結果」とし、以下を配置
  - 必要エネルギー
  - 蛋白
  - 水分
  - 推定CCr
- 右カラムは「参考項目」とし、以下を配置
  - 基礎代謝量
  - BMI
  - 標準体重
  - 肥満度
  - 体表面積
- 右カラムは常時表示ではなく折りたたみとし、必要な場合のみ開いて参照する構成にした。
- 必要エネルギーは dt/dd の流れを崩さない範囲で、フォントサイズとウェイトで控えめに強調した。
- 左右領域の区別を補助するため、PC表示のみ両カラム間に薄い境界線を追加した。

### モバイル 1列
- 折りたたみ見出しは「結果（参考・補足）」とし、参考項目を表示する構成に変更した。
- 主要結果の重複表示は避け、モバイルでは「上部＝要点」「折りたたみ内＝参考・補足」の役割分担を明確にした。
- 推定CCrに補正が入った場合は補足情報として参照できるようにした。

### 互換対応メモ
- IE系では nested details と polyfill の組み合わせで、open 属性変更だけでは本文表示が同期されないことがある。
- 狭画面時は result-details だけでなく reference-fold 側も開閉同期が必要。
- legacy details では open 属性だけでなく、必要に応じて summary 以外の子要素 display も直接同期する。


## 2026/02/15 必要エネルギーと経腸栄養の同期方向変更
### 変更内容
必要エネルギー入力欄と経腸栄養投与量の相互同期を廃止し、
**必要エネルギー → 経腸栄養量**の一方向同期に変更。

### 背景
- 経腸栄養量の変更で必要エネルギーが変わることに違和感
- 医療的には「必要量を計算 → 投与量を決定」が自然な流れ
- データフローが複雑で保守性が低い

### 実装内容
1. 算出方法から「手入力（Manual）」を UI 非表示
   - Enum 自体は削除せず（後方互換性）
2. 必要エネルギーに「× ボタン」追加
   - 手動編集を解除して自動計算に戻る導線
3. 投与量手動編集は独立動作
   - 経腸栄養欄内の計算には反映
   - 必要エネルギー入力欄は上書きしない
4. 状態保持を hidden + AJAX 同期で徹底
   - IsEnergyUserEdited / IsEnteralVolumeUserEdited
5. スマホでの経腸栄養欄の折りたたみを廃止
   - PCと同様に、経腸栄養計算を始めたら常時表示に変更

### 効果
- ユーザーの違和感解消
- データフローが明確化
- 実装の保守性向上
- スマホでの操作性向上


## 2026-02-04 UI設計変更
### 例外設定時の活動係数非表示制御を取りやめ
- 前回のUI設計変更で、例外設定時に活動係数を非表示にする仕様としたが、
  例外設定時もユーザーが算出方法を切り替え可能なため常時表示に変更
- 「算出方法」が「体重補正代謝量×係数」の時だけ活動係数を表示する方法も
  検討したが、あえて見せることで標準計算も可能なことを示せると判断

## 2026-02-03 UI設計変更
### 疾患セレクトの位置づけ整理
- 疾患セレクトは「疾患入力」ではなく、計算ロジック上の例外指定である
- 誤解を避けるため、表記を「疾患」→「例外設定」に変更

### 補足表示の簡略化
- 一般的注意書きおよび小児向け項目は、使用者向けUIとして冗長と判断し削除
- 例外設定が選択された場合のみ、疾患別の目安を常時表示する仕様に変更
- 折りたたみは維持せず、判断に必要な情報を即時視認可能とした

### 不要係数の非表示制御
- 例外設定時には活動係数が計算に関与しないため、
  `data-factor-block` でラップし JS で非表示制御を行う
- ストレス係数・褥瘡は蛋白計算に関与するため表示を維持

### 蛋白補正の手動選択状態の可視化
- 手動選択フラグは内部状態として保持
- UIの複雑化を避けるため pill 表示は行わず、
  PCでのみ気付ける tooltip により状態を補足表示


## 2026-01-21 UI設計変更
### 採用体重表示箇所の変更
- 基礎代謝量計算は実測体重、エネルギー計算では採用体重（実測・標準・調整）を使用しているため、
  採用体重は右列基礎代謝量欄から、左列必要エネルギー欄に移動
- 左列算出法の「基礎代謝量×係数」を「体重補正代謝量×係数」に変更：
  理論上の基礎代謝量とエネルギー計算に使用する代謝量をUIでも区別

### フォーム再送信確認の回避
- スマホで戻るボタン押下時に表示される「フォーム再送信確認」ダイアログを回避するため、
  フォーム送信をAJAX化
- スマホで戻るボタンは終了の意図と思われるのでそのまま閉じる仕様

### IEで左列・右列幅を調整
- IEで左列幅を52.5%→48%に変更し、左右バランスをモダンブラウザと同等に
