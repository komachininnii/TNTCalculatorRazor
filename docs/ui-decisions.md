# UI / 設計判断メモ

この文書は **現行UI方針の要約** と、保守時に参照価値のある **重要な転換点（Key shifts）** をまとめる。

---

## 1. Current snapshot / 現行方針の要約

### 1-1. 結果表示の優先順位
- 主結果（必要エネルギー・蛋白・水分・推定CCr）を第一面で表示する。
- 参考値（基礎代謝量・BMI・標準体重・肥満度・体表面積）は折りたたみ側に分離する。
- 目的は「BMRを必要エネルギーと誤認しない」情報設計。

### 1-2. 同期方向（エネルギーと経腸栄養）
- 同期は **必要エネルギー → 経腸栄養量** の一方向。
- 経腸栄養量の手動変更で必要エネルギーを上書きしない。
- エネルギー手動編集解除（自動計算に戻す導線）を用意する。

### 1-3. 互換・再発防止ポイント
- IE系では `details` の開閉表示同期に注意（`open` 属性だけに依存しない）。
- モバイルでは「主結果は常時把握、参考値は必要時展開」を維持する。

### 1-4. 不正 POST に対する enum 正規化方針

`[BindProperty]` で受け取った enum 値は、整数として任意の値を POST できるため、  
ドメイン層に到達する前に `RecalcAll()` 冒頭の `NormalizeBoundEnums()` で一括正規化する。

- 正規化は **silently fallback**（ModelState エラーにしない）  
  → 臨床ツールとして計算結果を返すことを優先
- `ClearModelState(nameof(...))` を必ず呼ぶことで、Razor の ModelState 優先問題を回避
- ドメイン層の `throw` は「正しい入力に対して計算精度を保証する」責務であり変更しない

### 1-5. 妊娠フラグの入力正規化方針

`IsPregnant` は単独の真偽値として扱わず、`Gender` / `Age` と整合していることを前提にする。  
通常 UI では妊娠チェックは「女性かつ 18〜55歳」のときのみ表示されるため、  
サーバー側でもこの条件に合わせて `RecalcAll()` 冒頭で入力正規化する。

- `Gender != GenderType.Female`
- `Age` 未入力
- `Age < 18`
- `Age > 55`

のいずれかに当てはまる場合は、`NormalizePregnancyState()` で `IsPregnant = false` に補正する。

補正時は `ClearModelState(nameof(IsPregnant))` も行い、  
Razor の `ModelState` 優先による表示不整合を防ぐ。

この補正は計算途中の個別処理ではなく、  
**入力境界で先に整合を取ってから計算へ渡す** ためのものである。

## 2. Key shifts / 重要な転換点

- 結果欄は「全表示」から「主結果と参考値の分離」へ転換した。
- エネルギーと経腸栄養の同期は、相互同期から一方向同期へ整理した。
- UI上の例外設定や補足表示は、判断優先で簡潔化した。
